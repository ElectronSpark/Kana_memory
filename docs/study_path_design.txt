学习路线设计与数据契约
版本：study-path-v1；设计记录日期：2026-10-26

目的

把现有可学习内容组织成“阶段 → 单元 → 小节 → 学习项”，让用户从首页继续学习，或按需要一次加入多个小节。路线负责选择内容和呈现进度；原有记忆单位、首次教学流程和间隔复习仍负责学习结果。用户不必每学完一项就重新查目录挑选下一项。

阶段、单元和小节的数量由当前目录与用户历史内容动态计算。不要把发布时某个数量硬编码进界面或据此推断用户能力。完整课程目录及覆盖统计以 build_study_path() 和发布校验结果为准。

一、编排依据与边界

研究台账：research/staged_path_research.json。它保存来源、适用范围、局限以及研究事实和产品推论的区分。

1. 以功能组织内容。JF Standard 用“能完成什么交际任务”描述能力；Marugoto 和 Irodori 提供主题、课程、活动分层的实例。因此单元尽量用“介绍身边的人”“安排活动”“说明理由”等用户可理解的用途命名，避免首页以内部语法分类为主。
2. 随阶段反复深化主题。基础阶段学习简单指示、动作和状态；之后扩大到经历、计划、连贯表达、判断辨析与正式表达。同一主题可以再次出现，但目标和语言材料应有进展。
3. 前置内容优先。GENKI 和东京外国语大学文法模块提供从基本句法、活用到复句和语体的现成顺序参考。现有学习项的 depends_on 是实际依赖契约；主题归组不能把有依赖的内容倒置或形成环。
4. 新内容先教后测。分段呈现研究支持让学习者控制进度，教材也先有说明和活动导入。第一次遇到语法时继续提供结构说明、例子和引导题，再进入独立提取。
5. 小节完成后仍须复习。提取与间隔研究支持把初次学习和后续保持分开。切换小节不会重置或提前旧项的到期时间；已介绍内容可以按原题型策略交错练习。
6. 小节大小是产品选择。研究不支持普遍适用的“每日最多若干项”“每节固定几分钟”或某个固定最佳题数。小节按用途、接续和易混关系划分；界面不设每日小节上限。

JLPT 的官方等级描述主要涉及语言知识、阅读和听力，不提供当前考试的官方逐项语法/词汇全集。JFT-Basic 和生活日语课程提供场景与题型参考，但不与本 App 逐课对应。路线不是“官方 JLPT 课程”；完成比例不代表通过考试、CEFR 认证或完整口语互动能力。研究台账中的推荐草案也不是对所有既有调度规则的覆盖性修改。

二、目录层次

阶段：当前主线由文字与声音入门、生活基础表达、日常交流与叙事、连贯表达与观点、阅读理解与用法辨析、正式表达与综合运用构成。字形与旧用法扩展、自选内容扩展另行组织，默认连续推荐跳过 optional 扩展。

单元：围绕相关功能或形式组织多个小节。较长单元可在语义主题边界拆分；出现跨单元相互依赖时需要重新组织单元，不能删除真实依赖来制造线性目录。

小节：一次选择的内容包。小节可混合呈现相关内容，但不能因加入小节而自动创建原本只供查阅的词典记忆项。小节中有新项，也可能有用户先前已经学习的项；再次加入只补尚未加入的内容。

学习项：仍使用原有内容身份。学习项可出现于课程主题中，但只拥有原来的一份学习记录。词典中尚未建立正式学习项的义项保留查阅用途；用户已单独加入的旧义项进入自选扩展，不因目录重排消失。

假名：平假名与片假名的学习身份分开。主线覆盖可用于现有题型的现代字形；不能独立出题的符号以 reference 保存。历史假名不阻塞现代主线。首学标题和字形展示仍沿用教学内容字体，界面指示使用 UI 字体。

三、用户流程

首页只突出一个继续动作。已有可进行的内容时显示“继续学习”；尚无加入内容时直接推荐下一小节。用户可以一直执行主要动作，也可以进入“学习路线”查看阶段和单元，或进入“添加内容”按阶段、单元、小节和学习项逐级多选。“按顺序选多节”仍接受任意正整数，只把下一批内容加入本次勾选，确认后才写入学习计划。

查看路线不改变学习数据。阶段与单元显示初学完成和未加入小节数；小节详情显示每项状态。词汇、语法和假名的技术 ID、数据库版本及来源说明不出现在主学习区域。

加入小节后先恢复已有工作，再按现有队列安排新内容。已输入的答案、未评分结果和引导题检查点可恢复。用户不是通过再次加入来重新开始；“加入”与“重做/重置”不是同一操作。

恢复时优先呈现已经提交但尚未评分的结果，再恢复有实质作答的题或引导检查点，其余候选保持既有顺序。空输入、音频播放状态和题目展示记录不单独抢占续学位置。恢复优先级仍受题型开关、暂停、前置依赖和原到期/冷却约束；不把排序变化记为学习事件。

首页与结束页还需考虑已保存复习安排、但尚未生成下一题快照的能力卡。这些只读预览复用实际入队的题型与到期规则，既不提前生成题目，也不改写复习时间；严格未来的最近到期时间可用于触发首页刷新。

首次学习继续使用原有流程：
  词汇、语法、读音规则：介绍 → 跟着做 → 间隔或插入其它内容 → 独立题 → 评分 → 后续复习。
  假名：原字形/读音介绍 → 保存介绍检查点 → 稍后独立题 → 评分与后续复习。
引导题不是独立成功证据，阅读介绍也不增加复习成功次数。

既有课程前置门槛保持不变：相关前置需要原系统认可的独立成功，或者用户明确自报已了解。路线不会偷偷替用户执行 acknowledge_prerequisites，也不要求全部前置达到长期复习“毕业”才能继续。等待期间可以显式加入其它小节；必要依赖仍按原规则优先。

课程结束或暂时没有到期题目时，提供继续下一节和添加内容入口，不强制返回平铺目录。继续下一节是显式追加动作；它不能以“继续”之名替换原题单，也不能把未来复习提前当作即时新题。

系统返回与左上角返回遵守既有规则：正在作答、引导或未完成教学时确认退出；已经保存进度的等待/完成页直接回首页。推进题目使用替换式页面导航，不能通过返回键回到已经评分前的旧题。

四、状态与进度的含义

new：没有已加入、介绍或评分证据。
partial：小节已有部分项加入，仍有新内容。
added：已经加入，但尚未有首学进展。
started：介绍/引导已有进展，尚未达到该项的首学完成条件。
completed：原学习记录表明该项已进行过首轮正式评分，或参考内容明确标记已读。

课程项依据 learning_content.stage 和原事件记录，假名依据原 script 身份的介绍、入队与评分记录，参考项依据显式已读记录。completed 只用于目录“初学完成”或“已读”，绝不写成“已掌握”。错误首答仍可能已完成一次初学，但其薄弱状态和近期复习继续由原调度器保留。

首页实际可答、等待到期、待介绍属于不同计数。未来到期题不能混入“现在可答”，已加入尚未评分项也不能再次算作未加入的新内容。阶段/单元汇总以小节为单位，小节内部以学习项为单位，标签必须写清单位。

五、技术边界与稳定身份

study_path_catalog.py：生成目录与拓扑顺序，输出稳定的阶段、单元、小节、entry 引用及 depends_on。目录快照不能修改输入内容对象。
study_path.py：StudyPathService 读取原记录推导进度；显式加入才更新路线 setting 和原 enrollment。ensure_kana_queue 追加假名题目，不承担新复习算法。
study_path_runtime.py：统一首页与继续入口，连接既有假名、课程和单词工具通道。
study_path_ui.py：路线浏览、小节详情和四级多选；study_path_selection.py维护只读选择与父级半选状态；learning_ui.py 保留原首学/问答并提供结束后的推进动作。

StudyStore 仍拥有假名记忆卡、main 队列和 word_romaji 工具队列。LearningStore 仍拥有词汇义项、语法与读音课程、能力单位、独立题和学习事件。不把假名复制成 LearningStore 卡片，不把课程卡复制成 StudyStore 卡片，不为阶段或小节建立另一份 FSRS 状态。

假名路线 entry 保留 content_id 与 script；课程 entry 保留现有学习项 ID、义项和能力结构。原题目快照、内容 revision、草稿、结果、曝光信息、评分事件和 due 时间继续由原表维护。

批量课程加入使用 enroll_with_prerequisites，原快照优先且再次 enrollment 幂等；append_questions 保留每能力已有 pending。假名追加使用原 session append token 与追加 API，允许同一物理假名的两个 script 身份分别加入，防止重新抽到已经入队但尚未评分的同一身份。

路线 setting 为 study_path_v1：version、added_sections、reserved_entries、reference_read。它记录用户追加意图与不属于记忆卡的阅读状态，不能反过来充当“已经掌握”的证据。按项添加只预留所选新项及真正的逐项前置，不扩大到同小节的无关项；整节全部加入后才计为已加入小节，部分加入另计。新课程与路线预留在同一事务提交，失败一起回滚。

六、等待、题型关闭和参考内容

所有已保存题型偏好继续生效。关闭某题型不删原题、不重排原 due，也不因下一节自动重开。重新开启后继续相同记忆身份；声音或手写服务未就绪时不制造评分事件。已经预约但暂不能生成题目的内容必须保留，并明确指向设置或服务准备，不能被宣布已经完成。

等待复习不是失败或丢进度。界面显示最近可复习时间，并允许浏览、结束今日学习或显式加入新小节。只有用户实际作答与评分才影响原复习安排。

reference 项保留原假名详情入口，用户阅读后可标记本节参考已读。它不拥有独立发音题、FSRS 卡或“掌握”状态。标记后仍应有继续学习和下一节出口，避免停在只读详情页中。

七、版本、备份和删除学习数据

当前路线 setting 版本为 1。没有该 setting 的旧安装与旧备份按原学习表自动推导进度，不需伪造批量完成事件，也不要求用户重新开始。保留现有内容 ID 和 script 是这一兼容性的前提。

目录变动与 setting 格式升级是两件事。目录可以调整主题展示和归组，但状态应依据稳定 entry/内容身份重新计算，而不是依据旧的“第几单元、第几节”。当前 setting 中暂时没有目录归属的旧引用应保留；已加入的旧课程快照仍应进入扩展展示，不得静默删除学习记录。

当前校验只接受明确支持的 version=1；尚未实现对任意未来格式的自动迁移。未来如改变 entry 身份、setting 结构或首次完成语义，必须提供显式迁移、映射与升级/降级边界测试。不要把未知版本默认当作空路线。

学习备份已携带 app_setting 中的路线状态，并在导入暂存区调用 validate_path_state 校验，然后才修改实时数据库。导入完整备份是恢复那个时点的记录，不能把当前路线状态擅自合并到历史备份。旧备份没有路线 setting 时，恢复后按旧学习记录重新推导。

“删除学习数据”一并清除路线预约、已加入小节意图和参考已读状态，以及原学习表；保留普通设置、题型偏好、安装内容、模型及既有备份文件。单纯进入路线页、换阶段或追加小节不会执行删除。

八、验证要求

发布前至少验证：所有现有项的覆盖与无重复身份、依赖无环和先后顺序；旧学习状态只读不变；同节重复加入与跨节共同前置去重；连续中断/追加/重启恢复原草稿和 due；当前题型关闭重开；参考已读无记忆事件；备份往返和删除学习数据；100%与200%字体、长标题、主要继续按钮和返回行为；各页面反馈快照能够还原阶段、小节和具体引用。

源码/UI测试通过与真机视听表现是不同验证。模拟器没有声音或手写服务时，应如实记录测试边界，不能声称已听取或识别实际输入。发布报告保存实际测试数量与设备证据，本文件不复制可能过期的发布数字。
