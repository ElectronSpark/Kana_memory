实验性日语语序参考汉译 v1
========================

产品规则
这是一份辅助理解日语结构的参考汉译，保留正常中文翻译，并默认折叠。
用户展开后才阅读它；不能把它当作答案、朗读文本或复习调度依据。
按用户更正，采用更积极的保序风格，不局限于现代汉语常见口语。
文言、近代及现代汉语已有的合法句法均可使用；先尽力保持日语各成分出现的顺序，
再选用能成立的汉语表达。可用话题前置、宾语前置及复指、者也／是也判断等结构。
例如“我是常山的赵子龙”可写作“吾乃常山赵子龙是也”，使身份判断收束在句尾。
这不是逐字换汉字或机械反转主宾语：语义忠实与中文句法成立是硬边界。
判断句、处所句、动作句须分别处理，不给每一句都加“是也”；也不一律以“把”
解决日语宾语在前。允许适量旧式词语，但不能添加身份、事件、情绪或文言装饰意义。
确实无法保序时，以正确中文表达原意，不能以生硬日式汉语冒充实验译文。

助词及虚词必须按功能处理，而非逐词配固定汉字：
- は／が与に／で／を：保留话题、主体、对象、地点及手段等关系，避免施受颠倒。
- も／だけ／しか／まで／までに：保留附加、限定和期限的范围；“只”不能错移到工具。
- 否定、条件、时态与体：分清部分否定、双重否定、反事实、进行与结果，勿凭空补已然。
- 授受、使役、可能与敬语：保留谁给谁、谁让谁、能否与许可；不机械拼接字面译法。
- よ／ね／でしょう等：结合上下文保留断言、提醒、确认和推测，不能一律译成“吧”。
主语或对象省略时不随意补人物；不能因为一个读法或词形有多义就替用户选定含义。
无法可靠译出专名，或整句关系、词义无法可靠确定时，保留 pending 原因，不猜译文。
text 只放中文译文本身，不以未核日文和解释性括号拼成译文；评审原因另存元数据。
英文词典导航、明确的中文释义等不展示为“日语语序”参考。
是否含假名不是语言判断规则；汉字同形日语、标题和万叶假名不得据此自动排除。

覆盖与审查边界：生成、二审、离线补齐和待核条目分别保留来源；结构校验不等于母语专家认证。

稳定绑定与接口
id = SHA256(JSON UTF-8 [source_text, source_translation])，JSON 使用
ensure_ascii=False、separators=(',', ':')。两端字符串须完全相同，不折叠空格、
标点或 Unicode。原文相同而正常汉译不同的条目不得相互借用实验译文。
译文对象只含五个字段：version=1、status="experimental"、source_text、
source_translation、text。缺失结果以 null 加非空 pending_reason 记录。
新增或修改原文／正常译文会产生新 id；旧绑定不能自动套用，需重新生成并审查。
AI 接口复用相同规则及校验器；可选附加字段不改变既有例句的正常显示与学习语义。

数据维护顺序（在代码仓库根目录执行）
1. 使用 .venv/Scripts/python.exe tools/collect_order_translation_corpus.py 收集实际文本对。
   输出 data/enrichment/order_translation_corpus_v1.json、覆盖报告及挑战输入。
2. 仅在已有 API 授权与安全密钥配置下运行 tools/generate_order_translations.py。
   输入公开语料，新策略完整批次写入 data/enrichment/order_translations_v2/batches/；
   模型、生成规则指纹和语境 id 绑定批次缓存，同一配置可续跑，不改写正常汉译。
   模型或规则变化需使用独立输出目录，避免把不同生成策略混为一次结果。
   本次激进保序策略先以 --corpus environment/order-translation-aggressive-pilot-corpus-20261029.json
   生成 32 条试验结果，并另设 --output 与 --report，不能混入完整批次目录；逐条通过语法和语义审查后，
   才切换回完整语料输入，使用该新策略独立批次目录完成全库生成。
3. 用 tools/audit_order_translations.py 进行第二阶段模型审校，保留积极语序，
   重点修正角色、范围、模态、条件及不能成立的汉语句法，不恢复为普通现代口语译文。
   输入为 data/enrichment/order_translations_v2/batches/，输出为该 v2 目录下的 audited_batches/。
   二审另有审校规则指纹并保留原批次绑定；它仍是模型审校，不等于人工母语认证。
   缺少首遍译文的 510 对另存 research/order_translation_review/offline_completion/
   的 part_*_output.json，逐句编写，脚本仅负责附加源字段和验证，不能覆盖已有候选。
   离线输出须声明本轮 policy_sha256、对应 input_file 与输入原始字节的 input_sha256；
   规则、输入指纹、完整条目顺序或源文锚点不匹配时，finalizer 拒绝构建。
4. 独立检查原稿及二审结果，审查语义关系和各时期汉语句法是否成立，保留精确审查报告。
   将采纳的精确修订写入 data/enrichment/order_translations_v2/editorial_corrections.json。
   每条必须有 id、previous_text、text、reason；text=null 表示保留待核／不适用。
   旧文本不吻合时须重新审查，不能无条件覆盖；合并报告时去掉重复 id。
   旧风格或原稿已采纳的语义意见可作审查线索，但 previous_text 必须绑定最终选中的当前值，
   即二审优先、其次原稿、最后仅用于补缺的离线译文，不能对未二审条目假称已经二审。
   order_translations_v1 的旧批次、构建报告及旧审查记录仅作历史证据保留。
5. 运行 tools/finalize_order_translations.py，按精确原稿指纹及语境绑定选择候选：
   有匹配二审结果时采用二审，否则保留新策略原稿，缺失项才采用离线补齐。
   不混入旧风格结果，也不以空白占位冒充译文；每条保留真实生成／审校来源。
   该脚本再调用构建器并应用精确修订，生成
   app/src/kanamemory/resources/order_translations.sqlite3
   只读附加库及构建报告。构建覆盖全部 12,926 对的结构检查：源文双绑定、版本及
   五字段对象、批次语境顺序、完整覆盖、冲突结果、pending 原因、修订旧值和 SQLite
   完整性。结构校验通过不代表已证明每条语义正确。
6. 运行 test_order_translation_corpus.py、test_order_translations.py、
   test_order_translation_ai.py、test_order_translation_ui.py，并手动核对折叠状态、
   长句排版及答题前防泄题。使用项目既有打包流程完成安装包验证。

安全与兼容
collector、generator、auditor、finalizer、builder 不读取或改写用户学习数据库，不传送学习记录给 API。
产物是可重新生成的公开语料附加库；运行时只读查询，不在线补译，不创建记忆项，
不改变评分、到期时间、未完成题单、作答草稿或首次学习状态。
查不到结果、绑定不匹配或附加库不可用时，保留正常原文和汉译，安全省略实验部分。
密钥不进入批次、语料、APK、反馈、备份或 Git。
