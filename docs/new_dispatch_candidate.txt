环境试验/Android 合成夹具均为测试数据，不能当作真实学习效果或真实手写识别质量证据。


策略及改动边界
1. 保持优先级 0 冻结反馈、1 实际输入草稿、2 真正到期短步、3 真正到期普通复习。
   只有当前实际可继续的候选都属于新任务时，才在课程与假名之间轮转。未来题/曝光冷却/前置/暂停规则仍有效。
2. 一个小 app_setting 保存 last_lane 与 last_kana_band。旧数据没有该字段时，新任务第一次给课程，随后按完成事件交替。
   不为旧队列捏造跨类别的精确入队时间。单类暂时空缺就继续另一类，没有为了等轮转而空转。
3. 假名采用现有 _ADAPTIVE_LEVELS：基础选择→输入/完整表→手写，在可用的非空组中循环。
   同组保留旧相对顺序及同内容相邻间隔；间隔规则不再允许绕过真实到期题或当前应服务的难度组。
   kana_choice 是看假名选罗马音，不是听音选择。
4. 课程已打开的讲解和跟做是连续块：保存过 instruction_exposed_at_utc 的 intro，或 guide，优先于其他新工作。
   完整跟做结束，或有效选择“已熟悉”跳过教学，才推进课程游标；intro_done 不推进。
   这条连续性不能抢占真正到期复习或冻结反馈/真实草稿。显式“跟着做一题”按钮原有的直接打开动作保持不变，统一分发边界仍执行真实到期优先。
5. 游标只在真实首次评分、有效教学块完成、有效熟悉路线转换的原 SQLite 事务中保存。
   验证了游标写入失败时评分、题目状态/索引、介绍状态一起回滚；重复保存不会二次轮转；成熟复习不会轮转。
   首次 Again/Good/Easy 与不开启公平选择的 oracle 产生完全相同的实际卡片与 due；不制造掌握证据。
6. 默认底层 API 保持旧行为，统一 UI 路线显式传 fair_new=True；独立假名/词例路线不会受新游标影响。
   旧手动 adaptive 无卡方向在统一路线里也归入 new，避免遗留的 (3,0) 优先级重新压住真正 due；独立旧练习的默认排序保留。
7. 新设置沿用现有备份表，补了严格字段/类型校验和清空学习数据时的删除。没有新增表或改变快照格式。

只读与关闭题型的精确含义
new_dispatch.read/choose_lane 与 learning.current 完全只读，重复访问不推进游标、不写调度记录。
既有 KanaLane.peek 内部调用 reconcile/prepare，本来就可能重排尾题及更新 checkpoint；此候选没有把它改成完全只读 API。
它不推进公平游标，不修改卡片/到期或评分。文档中的“peek 无副作用”仅指新增游标与学习证据，不否认原有队列规划行为。

旧 reconcile 将关闭的未评分题移入不可变历史，直接恢复逻辑只针对有真实卡的定时复习。
候选不修改此策略。实际 StudyPathService 重新开启已解锁方向时，保留旧快照并只创建一个活跃候选，不制造重复活跃题或新卡。
已有与新增合同都验证了这一路径；不能把“保留历史快照”描述为所有关闭题无条件原位复活。

验证内容
- 真实控制器：课程完整块→基础假名→下一课程完整块→输入→手写；重启保持游标和未完成块。
- 新课程不再永远排在旧未评分假名之后；真实 due、冻结课程反馈、假名文本/笔迹草稿的原优先顺序仍通过。
- 对原有“新假名固定先于新课程”的一项测试，候选只更新其政策预期，并增加旧题单/索引保留断言；没有改生产去满足测试。
- 快照原历史前缀、选项/metadata、assisted 索引、卡片与 due 保留；暂停/关闭候选不被选中，前置未满足的课程不能抢到新轮次。
- 初次假名介绍/熟悉路线、课程教学块、首次真实评分的事务回滚与重复提交；备份 roundtrip、坏游标拒绝与删除学习数据。
- Actor 与真实 UI 共用 choose_lane，课程 guide 不被新的 kana lane 打断；默认新模式、封存重启及旧模式拒绝切换。
- 17–19KB Android 合成导入夹具通过真实控制器路由验证。尚未使用 Android 设备手动触摸验证候选。

仿真与主程序一致性
隔离补丁中的新鲜 Simulation 与 CLI 默认 fair_new=True，与候选原生路线一致。
显式 --no-fair-new 用于复现旧分发；--fair-new 也可明确写出新模式。
resume 参数默认 None，读取 actor 封存值；旧 actor 缺字段按 False。显式改变模式会在开库前拒绝，不能用 performance-only review 绕过。
新模式写入 actor/summary/source segment；当前主四年结果不能贴上“新公平策略已验证四年”的标签。

应用后正式新轨迹命令（从新的、未使用的输出名开始，不续接旧 actor）：
.venv/Scripts/python.exe -X utf8 environment/simulate_long_term_learning.py --profile constrained --seed 20261027 --days 1461 --fair-new --lazy-kana --availability-check-every 137 --output environment/artifacts/long-term-fair-new-01
若先做 40 天定向试验，可加 --stop-after 40；后续使用同一模式和原封存日历 resume。新主轨迹仍需独立完成后才能比较长期等待与工作量。

最小 Android 手工验证
只在可恢复的测试模拟器中导入；先导出模拟器现有学习数据。此步骤留待主模拟完成、封存大历史夹具并应用/重包候选后执行。
生成器（补丁新增）：environment/create_new_dispatch_native_fixture.py。所有原始学习 JSON 仅留 .test_runs，不放宽 artifact 过滤。

A. new-work.json
首页继续→先看到“ている”课程熟悉度。选初学→讲解→跟做。阅读或跟做期间退回首页/重启，再继续，应仍回同一个未完成块。
完成跟做后进入基础假名。正确作答选“很轻松”以避免测试中新建短步打断观察。
之后应轮到一项课程新工作，可能是已满曝光等待的首测，也可能是另一课程讲解；不强行固定为第二个课程，实际等待时间仍有效。
完成课程新步骤后，下一次假名新机会应给输入/完整表，再下一个假名新机会应给手写，不再一直给基础选择。
输入部分罗马音或写几笔后退出并重启，继续应恢复同题及原输入。该部分需 Android 实际验证，不以控制器测试代替。
手写题型需模拟器已安装模型；夹具不声称测试模型识别质量，也不会用合成识别结果替代手动书写。

B. due-priority.json
首页继续应直接给「あ」的真实到期复习，不能先给新课程或另一新方向。该卡通过正常 record_review 创建，夹具生成时已过期约四分钟。
完成后查看卡片/复习记录：只有正常一次评分；新游标不能把原 due 改成“新内容”状态。

C. started-guide.json
首页继续应直接回到“ている”的跟做；即使 last_lane=course，也不能被假名新任务打断。
退出并结束 App 进程、再打开续学，仍是原跟做。答对并继续后，才获得下一个假名新机会。
做完导出当前测试结果用于比较，再恢复模拟器原备份。
