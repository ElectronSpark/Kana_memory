0 一句话方案
学习路线只是对同一份学习项目录的“导航视图”（阶段→单元→小节→条目身份），不拥有进度；掌握情况仍由
learning_unit（内容×能力，各自 FSRS）、study_card（假名×技能×书写系统）与事件表唯一保存。多条路线并存时，
条目身份（内容 ID、kana:<id>:<script>）跨路线共享，每条路线的条目状态都是同一份项级状态的投影；
“已选择学习”（reserved_entries）与“参考已读”（reference_read）是项级事实，跨路线共享；只有“整节已加入”
（added_sections）是路线级记录。依赖关系属于学习项（全局唯一、所有路线共享），路线只能据此排序，不能放宽
或新增硬前置。持久化只新增一个设置键 study_routes_v1（当前路线、各非核心路线的 added_sections 与规格），
study_path_v1 与全部进度表不改。

1 现状盘点（I，含代码定位）
1.1 唯一一棵路线树
- study_path_catalog.build_study_path(kana_rows, learning_items, extra_items) 用有效目录（含扩展库 contribution）
  生成唯一一棵“阶段→单元→小节→条目”树；阶段表 STAGES、PATH_VERSION、COHERENCE_RULES、GRAMMAR_ROUTE_CONFIG、
  PRONUNCIATION_ROUTE_CONFIG 是核心库 singleton（08 第 6.2 节）；WORD_TOPICS、GRAMMAR_TOPICS 等是 map_by_key/contribution。
- 条目身份：学习项用内容 ID（词/语法/读音规则），假名用 kana:<id>:<script>；参考条目同身份、kind=reference。
- 小节身份：section:<digest("<stage_id>|<unit_key>|<topic>|<depth>")>，单元 unit:<digest(stage|unit_key)>；
  与这棵树绑定，没有路线维度。小节 depends_on 由其条目的项级 depends_on 聚合（owner 不同则成边），单元内与
  单元间按前置先行做拓扑排序；_combine_micro_lessons/_weave_vocabulary 做小节合并与词汇穿插。
1.2 路线状态与学习进度
- 设置键 study_path_v1 = {version:1, added_sections[], reserved_entries[], reference_read[]}（study_path.validate_path_state）。
  added_sections 记整节加入；reserved_entries 记用户选择学习的条目身份（含自动加入的前置）；reference_read 记已读参考。
- 条目状态在读取时推导（StudyPathService._entry_states）：学习项按 learning_unit 的 stage（intro/guide/done、needs_teaching）；
  假名按 reviewed_kana_rows、kana_introductions_v1、主队列中的身份；参考按 reference_read 或 practice_retired 且已复习。
  即：进度本身已经是项级的，路线只决定“把哪些项放在一起看”。
- 进度表（learning_unit/learning_question/learning_event/learning_evidence/study_card/review_event/session_*）没有任何路线字段。
1.3 路线对调度的影响点
- StudyPathService.plan_kana_queue/kana_advancement_targets 枚举 self.sections/self.entries 中 kind=kana 且身份在 reserved_entries 的条目。
- add_sections/add_entries：按小节/条目闭包（learning_dependencies.build_dependency_plan、effective_dependencies、
  prerequisite_status）入学，写 study_path_v1 与 learning_unit 在同一事务（LearningStore.enroll 的 _after_enroll 回调）。
- 首页（study_path_runtime.refresh_study_home）读 overview 的 next_section、in_progress_sections、required_* 计数；
  “开始下一小节/学习下一小节”调用 _add_study_sections；continue_study_path 的派题本身是项级（LearningStore.current、
  ensure_kana_queue），不读路线。
- 其他读 study_path_v1 的地方：explicit_learning_start（reserved_entries 判显式开始）、example_store（reserved_entries
  判假名是否已加入）、progress_backup（validate_path_state）、learning_reset（删除该键）。
1.4 依赖关系的现行层次（08 第 9.1 节 L1–L5）
- L1 项级 depends_on（硬前置，首次教学先后）；L2 course_prerequisites 规则贡献；L3 题目 background_ids（出题门）；
  L4 包级 references；L5 包级 depends_libraries。前置资格 independent_ready_ids 来自真实无辅助成功事件，全局。
- effective_dependencies 对未动过且精确匹配指纹的已学项叠加当前目录的新增前置；已有真实作答/草稿/冻结结果的项
  保留原前置集合（preserves_existing_route——此处“route”指该项自己的前置集合，与学习路线无关）。
- 自报“我已了解前置”（checkpoint.prerequisite_acknowledged）是项级放行，不是成功证据。

2 目标与非目标
目标
- 多条学习路线同时存在、同时可用：用户可在任一路线中加入小节/条目并学习，首页有“当前路线”。
- 学习进度唯一：任何路线中的学习都更新同一份项级掌握状态；其他路线立即看到（同一次读取内一致）。
- 依赖关系唯一：硬前置属于项，所有路线共享；路线只影响顺序与呈现。
- 路线可来自核心库、扩展库（08）与用户目标（个人路线，分阶段）。
- 现有唯一路线成为“核心主线”，其小节身份、顺序、首页文案在只有它一条时逐字节不变。
非目标
- 不做每路线独立进度、独立 FSRS、独立到期；不做“同一项在不同路线不同掌握度”。
- 不改变任何题型、评分、辅助证据、四之二批引入、假名专项的规则；不新增每日配额。
- 不做不重启的内容库热切换（08 R1 仍成立）；路线来自库时也是重启生效。
- 不做路线间的“同步/合并进度”功能：无需同步，因为只有一份。

3 术语与总体模型
- 学习项（item）：有身份、有依赖、有进度的最小单位（内容 ID；假名则为 kana:<id>:<script>）。
- 路线（route）：route_id、标题、来源库、阶段表、单元/小节分组与顺序、条目身份列表的只读导航树。
  route_id = "route:<library_id>:<key>"；现有路线固定为 route:kanamemory.core:main（下称核心主线）。
- 路线集（RouteSet）：启动时由有效目录（08 EffectiveCatalogue）构建的全部可用路线，进程内一次，clear_cache 重建。
- 条目（entry）：路线中对某学习项的一次引用；条目身份＝项身份，同一项可出现在多条路线（每条路线内至多一处）。
- 小节（section）：路线内的最小可整体加入单位；小节身份带路线作用域（核心主线保持旧公式，见 6.4）。
- 路线状态（route state，路线级、持久）：该路线的 added_sections。
- 项级选择（item intent，持久、跨路线）：reserved_entries、reference_read（仍在 study_path_v1）。
- 项级进度（item progress，持久、唯一）：learning_unit/study_card/事件（不改）。
- 当前路线（active route）：首页“下一小节/初学统计”所指的路线；设置项，可切换。
  模型图：
    有效目录 ──构建──> RouteSet{核心主线, 库路线…, 个人路线…}
    项级进度（唯一） ──读时投影──> 每条路线的条目/小节/单元/阶段状态
    项级选择（reserved/read，唯一） ──┘
    路线状态（added_sections，每路线一份） ──> 该路线“做过整节加入”的记录

4 学习进度与路线分离：状态推导与跨路线影响
4.1 不变原则
- 进度表零结构变化；进度写入只发生在现有 Store 写入口（enroll/submit/finalize/record_review/…），这些入口不接收
  route_id，也不记录来源路线（12 Q4）。
- 条目状态函数 entry_state(item_progress, item_intent, entry) 与路线无关；RouteSet 对所有路线共用同一次
  _entry_states 计算（在 WP3 的 read_operation 内缓存一次），再按各路线的条目投影。
4.2 跨路线影响矩阵（A 路线中的动作 → B 路线可见变化）
  动作（在 A）                          项级结果                           B 中同一项/小节的表现
  整节加入（add_sections）              项入学 intro，reserved 增加         条目 added；小节变 partial/added；B 的“下一小节”跳过全 added 节
  按条目加入（add_entries）             同上（仅所选与其硬前置）           同上；B 中被动包含的前置也显示 added
  完成初学（stage done）                learning_unit stage=done            条目 completed；小节 completed 则 B 统计 +1
  取得真实无辅助成功                    independent_ready_ids 含该项        B 中以它为前置的项不再 blocked（无需任何写入）
  参考已读                              reference_read 增加                 B 中同身份参考条目 completed
  假名首次评分/复习                     study_card/review_event             B 中同 kana 条目 started/completed
  停用题型/暂停项（study_item_controls）项级控制                           两条路线都不派题，状态文字一致
  追加能力                              新 learning_unit                    两条路线无差别（能力不属于路线）
  B 的 added_sections 不会因 A 的动作自动写入：它记录的是“用户在该路线做过整节加入”；但小节显示状态
  （partial/added/completed）由条目推导，所以 B 看到的是真实情况。首页“已加入 N 节”按条目推导（fully_added），
  核心主线今天就已如此（_overview 用 new_count==0），不依赖 added_sections 计数。
4.3 “下一小节”的跨路线语义
- 每条路线各自有 next_section（第一个有 new 条目且非可选的小节）。首页只显示当前路线的；路线页显示每条路线的。
- 若 B 的下一小节的全部条目都已在 A 中学过，它自然不是“下一小节”（new_count==0）。
4.4 复习与到期
- 复习队列、到期、练习轮顺序（practice_round）均为项级，不区分路线；首页“现在可答/待到期”是全局数字。
  路线页可显示“本路线待复习 N 题”作为投影（按条目身份过滤同一份到期集合），只读。

5 学习项依赖关系的处理（决定）
D1 硬前置唯一且全局：L1 项级 depends_on、L2 规则贡献、假名依赖（practice_kana_dependencies、读音规则）与 L4 包级
   references 只属于学习项/内容库，所有路线共享同一份 effective_dependencies 与 prerequisite_status。
D2 路线不能放宽硬前置：路线规格没有 waive/skip 字段；“我已了解前置”仍是项级自报（prerequisite_acknowledged），
   在任一路线确认后对所有路线生效（它改的是项的 checkpoint，不是路线）。
D3 路线不能新增硬前置：路线规格可声明软顺序 after:[entry_id…]（“本路线建议先学 X 再学 Y”），只参与该路线内
   单元/小节的拓扑排序，不进入 prerequisite_status，不阻塞派题；软顺序成环时忽略并记诊断。
D4 路线外前置照常入学：在路线 B 加入小节/条目时，仍以 build_dependency_plan 求硬前置闭包（含不在 B 中的项），
   按 08 第 9.3 节 dependency_frontier 分批入学（首批＝词汇批量＋语法批量＋假名 5，可改“全部加入”）；
   预览页把闭包分为“本路线内 N 项 / 其他路线 M 项 / 不在任何路线 K 项”，后两类标出所在路线名或“目录项”。
   这些前置在它们所属路线中自然显示为 added/started（4.2）。
D5 路线构建时的前置标注：小节 depends_on 仍由条目硬前置聚合；若前置项不在本路线，小节记 external_prerequisites
   （身份列表），页面显示“前置在：<路线名>”或“前置不在任何路线（添加时自动加入）”。
   核心主线覆盖全部目录项，external_prerequisites 恒为空，输出不变。
D6 前置资格全局：independent_ready_ids 来自事件表；在任一路线取得的真实无辅助成功解锁所有路线中的后继，不写任何
   路线状态。后来遗忘/暂停不撤销（03 第 5 节不变）。
D7 库停用导致的前置缺失：沿用 08 第 9.2 节——已 ready 的前置保持 ready；否则后继 blocked，原因“前置所在的库已停用”；
   该项所在的路线若也来自该库，整条路线按 10.2 处理。
D8 同一项在不同路线中的“能力侧重”不改变依赖：能力是 learning_unit 维度，由设置与追加能力决定；路线规格首版不含
   能力字段（12 Q5）。

6 路线来源、规格与构建
6.1 三类来源
- 核心主线（I→保留）：由现有 build_study_path 用核心 singleton 配置构建；route_id=route:kanamemory.core:main；
  覆盖有效目录中全部学习项与假名（含扩展库 contribution 进来的项，与今天一致）。
- 库路线（P）：扩展库（或核心库自身）在教学分层新增命名空间 study_routes（合并策略 items_by_id，键为 route_id；
  route_id 必须以本库 library_id 为前缀，否则预检拒绝）。一个库可带多条路线；路线只能引用有效目录中存在的身份〔R4b 注：此处“预检拒绝”按实现改为“预检警告、安装后忽略”——前缀不符或完整校验（validate_route_spec，含身份须在有效目录）失败的路线列入 PackPrecheck.route_errors，不阻塞安装；合并整条丢弃前缀不符者，RouteSet 跳过校验失败者，库行以 routes_ignored 显示；见第 13 节 R4b 与 08 第 16.6 节〕
  （本库 provides 或 references 声明的项；缺失按 08 L4 语义：required 缺失→该条目 blocked_dependency 并在路线页显示）。
- 个人目标路线（I，WP-R5 2026-11-08）：用户在添加页选择若干目标项后“保存为路线”，规格存 study_routes_v1.routes[route_id].spec
  （route_id=route:local:<uuid>），内容＝目标身份列表＋可选分组；条目闭包在构建时由 build_dependency_plan 求出并
  按 12 Q3 并入或只标 external。
6.2 路线规格（study_routes 命名空间条目 / 个人路线 spec）
  { route_id, title, description?, library_id, version,
    stages: [ { id, title, optional?: bool,
                units: [ { id?, title,
                           sections: [ { id?, title, optional?: bool,
                                         entries: [ "<content_id>" | "kana:<id>:<script>" | {id, kind: "reference"} … ],
                                         after?: [ "<entry_id>" … ] } ] } ] } ],
    build?: { kind: "filter", select: { tags?: [...], families?: [...], ids?: [...] } }   // 二选一：显式 stages，或由目录筛选自动分节
  }
  校验（纯规则 study_routes.validate_route_spec）：route_id 前缀、身份存在于有效目录、同一路线内条目身份不重复、
  显式 stages 的 optional 标记合法、after 只引用本路线条目、总条目数上限（20000，与 validate_path_state 一致）。
  build.kind="filter" 时用现有 build_study_path 的分组逻辑（_learning_route/_kana_route/coherence）在筛选出的子目录上
  构建，使“JLPT N5 子集路线”之类不必手写小节。
6.3 构建算法（纯规则 study_routes.build_route(spec, catalogue_view, kana_rows)）
  1) 解析条目身份→条目记录（kind=learning/kana/reference，沿用 build_study_path 的条目字段）；
  2) 条目硬前置＝目录 depends_on（入学期再按 effective_dependencies 重算，与今天一致）；
  3) 小节 depends_on＝条目前置聚合（owner 在本路线内）；external_prerequisites＝owner 不在本路线的前置身份；
  4) 排序：单元间、单元内按“硬前置先行 + 软顺序 after + 作者给定顺序”拓扑排序（复用 _topological/_merge_cyclic_units）；
  5) 可选阶段/小节标记沿用 optional；
  6) 输出与 build_study_path 同形的树（version、stages[...]），外加 route_id、library_id、external_prerequisites。
6.4 小节与单元身份
- 核心主线：保持现公式 section:<digest(stage|unit_key|topic|depth)>，使 study_path_v1.added_sections 与所有旧记录不变。
- 其他路线：section:<digest(route_id|stage|unit|section_title|position)>、unit:<digest(route_id|stage|unit)>；
  显式规格给了 id 时用 "<route_id>#<id>" 形式的稳定 id，升级库时作者可保持 id 不变。
- 条目身份永远是项身份，不带路线前缀（否则进度无法共享）。

7 持久化、备份、重置与迁移
7.1 设置键
- study_path_v1（不改）：reserved_entries、reference_read 继续作为项级选择；added_sections 继续作为核心主线的路线状态。
- study_routes_v1（新，一条 JSON）：
  { version: 1, active_route: "route:kanamemory.core:main",
    routes: { "<route_id>": { added_sections: [...], enabled: true, source: "library"|"local", library_id,
                             created_at_utc, spec?: {…个人路线规格…} } } }
  校验函数 study_routes.validate_routes_state（形状、route_id 前缀、added_sections 去重与上限、active_route 存在或为核心）。
  缺省（键不存在）＝只有核心主线、active_route 为核心主线：旧安装无需迁移。
7.2 备份/恢复：progress_backup 导出携带 study_routes_v1 并校验形状（与 study_path_v1 同范式）；恢复时按原样写回；
  路线所属库在本机不存在时，该路线状态保留、路线显示为“所属库未安装”（10.2），不拒绝恢复。
7.3 learning_reset：与 study_path_v1 同样处理（一并删除）；个人路线 spec 是否保留见 12 Q6。
7.4 写事务：路线状态写入沿用现有模式——add_sections/add_entries 在 LearningStore.enroll 的 _after_enroll 回调里

11 风险
R1 两条路线覆盖同一批项时，用户可能误以为是“两份进度”；靠文案（“同一进度”）与路线页的“在其他路线中已学 N 项”提示。
R2 核心主线输出必须逐字节不变：构建路径重构要以黄金对照守住（小节 id、顺序、条目字段、首页文案）。
R3 reserved_entries 继续是全局集合：从 B 加入的条目会让 A 中同身份条目显示 added，这是设计意图，但旧测试可能假设
   “未在 A 加入则为 new”。
R4 并集读取点漏改会让非核心路线中加入的假名不进队列：以表征测试覆盖 8.2 每个读取点。
R5 个人路线闭包很大时的首学积压：沿用 dependency_frontier 分批。
R6 route_id 冲突：库前缀强制 + 预检拒绝；个人路线用 local 前缀。

12 开放问题（需用户决定）
Q1 首页是否同时显示多条路线的“下一小节”（建议：只显示当前路线 + 一行“其他路线”摘要）。
Q2 核心主线是否允许被隐藏/停用（建议：不允许，它是全部目录项的兜底视图）。
Q3 个人路线的硬前置：构建时并入路线（显示为“自动加入的前置”单元）还是只标 external（建议：并入，单独成“前置”单元）。
Q4 是否在诊断/事件中记录“来源路线”（建议：不记；进度表与事件表零变化，只在 UI 流转中传 route_id）。
Q5 路线是否可声明能力侧重（如只练识别）（建议：首版不做，归入 P-02 假名同能力归一之后再议）。
Q6 learning_reset 是否保留个人路线规格（建议：保留规格、清空 added_sections，与“删除学习数据不删设备配置”一致）。
Q7 库路线是否允许引用不在本库 provides/references 中的核心项（建议：允许引用核心库任何项，但须在 references 中声明为 optional 以便预检）。
