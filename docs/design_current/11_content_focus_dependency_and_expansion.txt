0 一句话方案
把“题目能不能用中文做出来”和“题目有没有用到还没学的东西”变成两条可计算的规则，内容与代码各管一半：
内容侧给每个学习词一个同形词等级（S/P/D/E），按等级决定哪些题型该退役、哪些要改成只接受假名或纯日文选项，
并为每条题目模板离线算出“依赖集”（它用到的词、语法项、假名）放在模板外的旁路命名空间里；代码侧在选题时用
同一份学习进度（讲解已出示的项）过滤依赖未满足的模板，并保证每个“项×能力”至少有不依赖他词的退路题。
主线把 ます形与格助词等 15 个骨架语法项提到阶段 1 开头，并把高频基础词提前、补入词表外高频词；阶段 2–4 分批把
词汇从 349 扩到约 1,600（以词库 2,000 核心词 + 1,000 外来词为池），每单元 8–12 个新词，每个新词按等级配齐
读音／字形／用法／听力四类纯日文题，使早期每格有 ≥2 道“只用已知词”的题。

2 目标与非目标
目标
- T1 任何题目都不能靠“看见中文／看见与中文同形的汉字就答对”；同形词的练习落在读音、字形辨认、日语语境用法与听辨上。
- T2 默认主线从零学起时，题目与例句只用已引入的词、语法项与假名；识别类题目最多含 1 个带内联注释的未知词（第二阶段）。
- T3 每个“项×能力”在其引入时刻至少有 2 道（目标 4 道）只用已知材料的题；新内容 ≤ 30%，每单元 8–12 个新词。
- T4 词汇从 349 扩到阶段 3 结束约 920、阶段 4 结束约 1,600（池：词库 2,000 核心词 + 1,000 外来词 + 补充词），表达（寒暄、课堂用语、句末助词、量词）补齐。
- T5 假名阶段只用已介绍假名；阶段 1 起汉字全注音，读音题隐藏目标词注音；注音随掌握度隐藏（第三阶段）。
非目标
- 不改 FSRS 参数、能力划分的证据权重、记录格式；不改旧题快照与已出题的文字；不删除历史模板（只退役／改绑）。
- 不引入新的题型插件框架（沿用 question_kinds 注册表）；不做 AI 实时出题；不改公开/私有边界（内容仍私有）。
- 本轮不做汉字独立教学（单字课），以注音与“整词内教”代替（C 的 Duolingo 做法）。

3 术语
- 同形词等级（cognate class）：S（a/b/c 及字义透明的 p：中文读者看字即知义）、P（部分同形且不透明）、D（异形词／假朋友）、E（纯假名词）。
- 依赖集（requires）：一条题目模板为被理解所需的内容项集合：词 id、语法项 id、假名 id；由分词离线推导，存在模板之外。
- 已知集（known）：学习者当前“讲解已出示”的项（study_queries.instruction_ready_ids）∪ 当前批次条目∪ 已介绍假名；
  是单份学习进度的投影，与路线无关（10 的原则）。
- 退路题（fallback）：依赖集为空（只含目标项）的模板，例如单词变体、假名拼读、读音选择。
- 1T 允许（第二阶段）：识别类题最多 1 个未知实词，且模板提供该词的注音＋中文内联注释。

       连放；该扩展库的 76 项都有人用到）。插入后在最终顺序上重新检查全部保底；移来的项自己刚学到时的门控题不少于推导顺序（测试里断言）。
M9 保证（由构造得到，测试固定）：硬前置都在前；骨架小节与被往后匀的库语法项刚学到时每种能力的门控题不少于推导顺序；可动小节里的项

   库语法项的题。不保证（代价，如实量）：提前的项刚学到时的门控题可能变少（不低于保底）；按“已学的词数”计有的词比原来晚（别的词排到了
   它前面）；单元成员变了。

16.4 对已有学习者的影响（P）
- 学习 ID、FSRS 状态、到期、草稿、未完成队列、作答与评分记录、学习数据库结构：都不变（路线只是导航，10 第 4 节）。
- 已加入的小节（study_path_v1.added_sections）：核心小节 id 不变（内容不设主线开头的给定顺序时；设了的见本节末条），记录照旧；库的大节切开后旧 id 留在记录里、统计忽略。小节、单元、阶段的
  已加入／进行中／完成本来就按条目推导，不受影响。
- “加入下一小节”：取交替后顺序里第一个还有新条目的小节。学到某段中间的人，会先拿到被提前、还没加入的词小节，再往后走；已加入的不会
  重复加入。已经把某段的语法都加入了的人，该段剩下的只有词（没有语法可隔）。
- 学习重点（设计 12，arrangement/sources/scope_kinds.py 的 NodeScope）：阶段范围的成员不变（被往后匀的库语法换了阶段）；核心小节范围不变；
  库的大节范围失效（显示“所选范围（已停用或不存在…）”，可以清除，与已交付学习库换小节 id 时相同）；骨架单元的 id 不变，但成员会变：
  排进来的可动小节加入，本单元原来的词小节若被提前到更前面的骨架小节之前就归了那个单元（范围可能变大也可能变小）；被拆散的只有词的
  话题单元失效。
- 内容更新或启用、停用库之后，后台算完之前主线是推导顺序，算完之后是交替顺序；换树不写任何学习数据。
- 主线开头的给定顺序（study_path_catalog 的 MAIN_ROUTE_ORDER，07“主线开头的给定顺序”）：不设时任何 id 都不变。装上或改动它时，
  变的 id 正好是这两类，阶段 id 与学习 id 都不变：
  (1) 开头的小节与单元：id 是所含内容的摘要（小节：阶段与所含课的 id；单元：阶段、单元标题与第一节的 id），所含课或单元标题一变就变；
  (2) 其余的课照原规则重新组装（少了被选走的课，_combine_micro_lessons 可能合并别的邻居）：所含课的集合与不设顺序时同 id 的小节或
      单元不同的小节或单元（课被选走而变少的、与别的邻居合并的）换成由所含内容生成的新 id（摘要“main-rest|阶段|课 id…”，
      main_route_order.renew_rest_ids）；所含课相同的、以及不设顺序时没有这个 id 的（如拆开的长单元），保持原 id。
  所以学习重点或已加入记录里的旧 id 不会悄悄指向别的课：它要么仍指同样的课，要么失效（重点显示“所选范围（已停用或不存在…）”，
  可以清除；已加入记录里的旧 id 留着、统计忽略，与库的大节切开时相同）。改动顺序时，同一内容的小节或单元得到同一 id。

16.9 按设置组保底（I，2026-11-14；合成数据单元测试、真实内容桌面对照，本轮未经独立审计，原生未验）

  service（main_route_mix 按参数区分同一数据目录下的混排对象）。中间试过按题型保底（算法版本 2），保的比学习者能设的多、代价更大

  装上该扩展库 840 → 576。

16.10 保底跟学习者自己的开关（I，2026-11-14；合成数据单元测试、真实内容桌面对照、一轮独立审查；模拟器上看过一次，见末条）
- 起因：16.9 的代价全部来自一个设置组“读句选词（无中文）”（题型 vocab_context_choice，能力 use）。同一能力里默认开着的其余题型只用词，
  所以在默认开关下，“每种能力在开着的题型里至少留 1 道”不改变任何位置；只有在 use 上只开读句选词的学习者，这道保底才起作用。
  于是不再替所有可能的开关组合保底，只保这位学习者自己开着的。
- 规则（M5 末句）：第二道保底按学习者开着的题型（learning_questions.stored_enabled_kinds，设备检查之前的设置；没有保存过设置时即默认
  题型）。每个可动项、每种能力，原位置在开着的题型里有门控题的，新位置至少留 1 道；每种能力 min(原位置时的数量, 3) 照旧，算所有题型。
  开着的题型（排序后的列表）进方案的键；算法版本 5，已存的方案重算一次。空列表（什么都不练）没有这道保底。保存的设置损坏
  （“开着的题型”不是列表）时，方案这一侧同样当作没有开关；出题一侧对损坏值另有自己的读法，两侧不保证一致，只在设置损坏时出现。
- 开关改了以后：设置在主线程上、建混排对象时读一次，以纯数据交给 route_mix。同一次运行里改开关，方案照旧使用；下次启动时键里的
  开关与存着的方案不同，先沿用存着的方案（同一内容、同一推导树、同一算法，只是按旧开关算的），后台算好新开关的方案后换树，
  中间不退回推导顺序。只存一个方案。内容、推导树或算法不同的方案仍然不用（先按推导顺序），与之前相同。
- 实现：params（MixParams.kinds、switched_kinds；去掉 groups、kind_groups）、readiness（choice_key＝"on:<能力>"；去掉 group_key、
  kind_key）、sources（开着的题型的模板另记在 choice_key 下）、plan（same_apart_from_switches：两个键除开关外是否相同）、
  service（mixed 接受只差开关的方案；current_for 说存着的方案是不是按现在的开关算的；prepare 仍按整个键判断要不要算；
  main_route_mix 同一数据目录沿用原对象）、study_path（route_mix_job：正在用的方案不是按现在的开关算的，就仍交出计算任务，
  否则启动预热不会去算新方案）、study_path_runtime（传入开着的题型）。排法本身不变。
- 结果（桌面，只有核心内容，2026-11-14 上午的内容）：默认开关下的方案与不加这道保底的方案逐项相同（条目次序与单元都相同）。最长连续
  单词／非词项，阶段 1–5 依次 15／4、19／9、7／12、5／9、5／4（16.9 为 17／4、31／20、7／12、5／9、5／4）；超过 16 的连续单词 24 段，
  超过 3 的连续非词项 51 段，提前的项 807 个。按 App 的出题策略逐项检查，默认开关、加日文键盘、语音未就绪（有、无键盘）四种情形下，
  从有门控题变成没有的（提前的项，能力）都是 0。只开“读句选词（无中文）”的学习者，按自己的开关算出的方案 0 例，代价同 16.9

  1.0 秒：开着的题型的每个模板多记一行）。

16.11 编写一侧的工具：给定开头的检查与排序（I，2026-11-18；合成数据单元测试，真实内容上跑过一次，未经独立评审）
- 检查：tools/check_main_route_order.py（07“主线开头的给定顺序”）。开头的每一课、每个键都要有 min(不设顺序时的门控题数, 保底)
  道门控题；混排从不移动开头，所以这道保底只能由内容守住。
- 排序：tools/arrange_main_route_order.py。想要的顺序把课提前，常常让它们的题要用的课排在后面；一课一课删掉不过的课再查，
  剩下的很少，而且删掉的课本可以晚一点放。工具做相反的事：不就绪的课往后放，直到就绪；本来就绪的课保持原来的相对次序。
  用的是检查的同一套函数（保底、计数、阻碍的排法）与 route_mix 的准备度表，结果由检查工具核对，有错就失败。
- 只靠列表里的课永远不能就绪的课留在外面，报出挡住它的要求；再按贪心排出列表外最值得加进来的课，以及它每加一课累计能放进
  多少课。课与课互相需要（一组课各自的题都要用组里别的课）时，单加一课常常一课也放不进：这一轮取“假如它就绪能放进最多”的
  一课，标为 if ready，它在列表里等着，后面加的课让它就绪时，它与它放进的课一起进来。累计数总是按就绪规则算的。
- 不做的：不为连续段重排（只报告检查的最长连续段）；不改题、不删题；结构化的输入排成平铺的顺序。

18.1 现状（I，2026-11-14，只读盘点，核心内容）

18.2 作者写的字段（只写在新模板上）
模板指纹包含整个 practice，给已有模板补键会换掉它的指纹，以及按指纹存的依赖、读音、退役、注释与题目快照的重建。所以写进
practice 的字段（Q1、Q2、Q3a）只在写新模板时给出；旧模板要改就按本设计的既有做法追加新模板、退役旧模板。注释（Q3）放在模板
旁边，可以后补。
Q1 practice.opens_after_reviews：整数 0–40，缺省 0。该项×能力的计分复习次数达到这个数之后，这条模板才参加选题（Q5）。它只管
   先后，不替代依赖门控，也不得为了错开时间往 background_ids 里加无关的项。[I：格式校验，learning_questions.validate_practice]
Q2 practice.scenario_id：^[a-z][a-z0-9_]{0,63}$，题目所在的生活场景。场景表是可选命名空间 question_scenarios：
   {"schema_version":1,"scenarios":{场景 id:{"title":…,"summary":…}}}；用到的 id 都要在表里（构建时检查）。App 目前只校验
   格式、不读场景表；同一项×能力内的轮换仍按 context_id。[I：格式校验；场景参与轮换：未做]
Q3 题干生词的注释：作者只给打算“在这个词学会之前就放出来”的题写注释，每个这样的词一条（题干里的写法、读音、中文；是词课的
   写词课 id；写法在题干里出现多次时给出位置）。构建工具把它写进该模板的 contexts[模板指纹].background_glosses，即 0.28 起就有的
   逐题背景注释通道。注释按指纹放在模板旁边、不属于模板，所以也可以给已有的、现在出不了的模板补注释而不改模板。
   一条注释只有在 App 会把它显示给不认识这个词的学习者时才收：位置与题干一致、不压目标片段、不与别的注释重叠、不出现在答案
   与选项里、释义不泄露答案；多空题不收注释。这条通道只存在于 varied_practice 与 context_choice 两个绑定命名空间：contexts
   按模板指纹存在它们的记录里。写在课自己的 question_templates 里的模板没有这条通道，带不了注释；学习库同此，要带注释的题
   放进库自己的这两个命名空间。[I：tools/practice_authoring_fields.py（作者字段的统一处理，条件与
   question_support 的显示过滤逐条对应，有对照测试），tools/compile_reviewed_question_batch.py 与批次合并工具都经它写入]
Q3a 作者声明的依赖 needs：推导工具认不出的结构（并列名词的と与表示同伴的と、表示结果状态与表示进行的〜ている、修饰名词的
   从句等）会让题在那条语法讲过之前放出。新模板可以在作者字段 needs 里写 1–8 个它真正依赖的课 id（词、语法、假名、读音规则
   均可；没有就不写这个字段）。并入时它们排在 practice.background_ids 的最前面，后面才是推导出的词与语法（合计至多 40，
   超出时只舍推导出的）。App 的门控取 background_ids 与 question_dependencies 条目的并集（第 5 节 D1–D3），所以以后重新
   推导也不会丢掉它们。needs 只写真实依赖，不用来错开时间（那是 Q1）；审查像核对答案一样逐条核对。每个 id 必须是课程目录里的
   项，不是本题的目标，不是新词的占位 id，并且排在路线上：不在路线上的，那条题不并入（它永远开不了）；排在目标之后的照常并入，
   学到那里才开。它属于 practice、进入指纹，所以只能写在新模板上。
   [I：tools/practice_authoring_fields.py 的 needs_ids／background_ids；tools/build_question_batch.py 把紧凑写法里的 needs
   传进字段文件，并拒绝占位 id；批次合并工具写入，并按推导预检所用的路线文件检查（有 needs 而不给路线文件时拒绝）；
   tools/compile_reviewed_question_batch.py 拒绝这个字段，它的行自带经审查的 background_ids 列。推导工具的预检
   （--check-staging --fields）把 needs 与模板自带的 background_ids 一样放到路线上检查，报告里以 needs 一栏列出：不在路线上
   或排在目标之后的算未引入，注释不能顶替它]
18.3 构建写下的事实（question_dependencies 条目的两个可选字段）
Q4 stem_words ⊆ words、stem_oov ⊆ oov：这条模板所需的词里，同时满足下面各条的那些——
   a) 只在题干出现：不在答案、可接受答案、任何选项里；多空题一律不标（填进空位的词与题干分不开）。意义类题里只写汉字的
      选项推导工具当作中文、不切分，所以“选项里不放未学的日文词（含只写汉字的）”由出题与审查保证；
   b) 模板给它写了注释（Q3）；
   c) 是词课的词时，它自己的课在核心推导顺序上排在本题所属项之后至少 50 个学习项。离得近的不标：那样的题等这个词学过再开，
      免得刚看过注释就去学它，第一次学习时量不出真实的熟悉程度。课程外的词不需要间隔。
   两个字段不增加也不减少任何要求，只是给 Q6 用的标记；校验要求它们是各自基础列表的子集。
   [I：格式校验，content_pack.validate_question_dependency_requirements；推导工具写出这两个字段（2026-11-14：去掉它们后与
   不写时逐字节相同；注释取自该模板 contexts 里的背景注释，词课按 target_id、课程外的词按注释位置覆盖词元；距离按工具载入的
   路线计，--stem-distance 可改；今天的核心内容有 415 个模板得到标记）。预检 --check-staging --fields 按批次的注释报告每个变体
   覆盖了哪些题干生词、注释层是否成立]
18.4 选题规则（I，2026-11-14；合成数据单元测试，核心内容上新旧选题逐项对照相同，原生未验）
Q5 放题：模板的 opens_after_reviews 大于该项×能力已有的计分复习次数（learning_unit.review_count）时，这条模板不参加选题，
   也不记为内容缺口，不进放宽层。调用方没有给出复习次数时按 0 算：讲解页、入门小测、只检测的试做本来就是 0 次；诊断与家教
   暂时也只用 0 级的题。撤题替换读得到单元的复习次数，按同样规则放题。已经排进队列的题不受影响。每个项×能力在 0 级至少要有
   6 道严格可出的题，由内容侧保证。
Q6 注释层：只有调用方明确允许时才有。现在允许的是正式课程路径（复习，以及首页、加课页、工作量预估对它的预览）；练习卡组的
   页面还没有背景注释行，暂不允许；讲解页、入门小测、只检测的试做、诊断、家教、撤题替换都不允许。一条模板可以
   带标记 stem_gloss 出题，当且仅当：它未满足的要求有 1 个或 2 个，全部在它的 stem_words／stem_oov 里；其中没有学习者已经加入
   课程的词；它不是多空题。未满足项里混着语法、读音规则或没有标记的词的，不进这一层。
   位置与第 5 节 D8 的开头放行相同：排在全部要求已满足的题和补位题之后，不替换、不遮挡它们；一道都没有满足时，它与开头放行
   的题一起先于放宽层。与开头放行的题同时存在时排在它们之后，按题面去重。同分时没有注释的题在前。学习者已加入的词只在
   确有模板够条件时才读一次（每课至多一次查询），没有题干事实的内容不多花任何读取。
Q7 页面：题干下方用现有的背景注释行显示这些词的释义（学习者已经独立掌握的词不显示）；读音按第 7 节规则 3，未学词总带假名。
   结果页不显示注释。
Q8 主线交替的准备度（第 16 节 M5）只数 0 级、要求全部满足的题；注释层的题不计入（偏保守）。opens_after_reviews 不是整数 0 的
   （含格式不对的）都不计；route_mix 的算法版本升为 4，已存的方案重算一次。
Q9 不改学习记录格式，不改记分：带注释的题对所属项×能力照常记分；被注释的词不记任何证据，也不算已学。
18.5 没做的与取舍
- 没有“这个词被注释展示过”的持久记录（那是记录格式的新增，要用户同意）；与第一次学习的间隔靠 Q4 c 的 50 项距离和 Q6 的
  “已加入的不注释”两条放置规则保证。
- 一题仍只对一个项×能力记分。
- 练习卡组与家教还没有注释层：卡组页面要先有背景注释行；场景（Q2）还不参与轮换。
- 旧版 App 不认识 Q1、Q2 的两个 practice 键与 Q4 的两个依赖字段：带这些内容的课程包与学习库需要本版或更新的 App（学习库在
  manifest 的 requires 里写明）。Q3 的注释与 Q3a 的 needs 走原有的通道（背景注释、background_ids），旧版照常读。

19 外来词的来源语言与来源词（决定 L1–L7；2026-11-14）
原则见设计 14 第 7.2 条。本节是数据合同、程序规则与显示位置。
19.1 现状（I，2026-11-14，只读盘点）
- 片假名书写的核心词课 46 个，没有一个带结构化的来源；讲解文字里偶有提及，不成格式，个别还会误导。
- 沿学习路线走的页面都不显示来源；只有词典详情页显示词库里未经审核的 Wiktionary 数据，标签写死“英语”，非英语来源无处显示。
19.2 数据合同
L1 可选教学命名空间 loanword_origins（v1，整份不分片）：{"schema_version": 1, "items": {词课 content id: 条目}}。不写进词课的
   讲解或规则文字：那些文字属于词课指纹，也属于课计划的来源字段。
L2 条目：title 与 reading（绑定：与词课不等即为过期，不显示，由内容检查报告）；kind；sources [{language, word, part?}]；
   full_form?；reason?；note_zh?（至多 120 字）；evidence.source_ids（1–8 个不同的出处 id）；review.status（candidate｜reviewed，
   可选 by）。
   kind 与它要求的字段：
   - direct：恰一个来源；
   - multiple：两个以上来源、至少两种语言（共同来源或并存的说法）；
   - clipping：来源是未缩略的原词，必填 full_form（未缩略的日文形式，假名）；
   - wasei：来源是构词成分，依次列出；full_form 只在它本身又是缩略时写。长形式在原语言里真实存在的缩略词是 clipping，不是
     wasei（コンビニ、スマホ 属于 clipping）；
   - hybrid：每个来源带 part（标题里它解释的那段片假名，须是标题的子串）；
   - exempt：没有来源，必填 reason：mimetic（拟声拟态词）、sino_japanese（汉语词）、native（和语）——三者只是写成片假名；
     coined（为作品造的名字：角色名、作品里的专名，没有哪种语言的词是它的来源；2026-11-14 增）。外国的地名、人名与神话、
     宗教里的名字不豁免，按外来词写它传进日语时所经的语言（设计 14 第 7.2 条）；从造出来的名字里拆出的普通外语词也照写来源。
   language 取程序里的列表（en pt de nl fr it es ru la el ko zh sa ar，另有 ain），词典里的三字母代码由预填工具转换；word 是
   原文拼写（保留变音符），1–80 字符，不含假名与 [ ] # |。part、reason、full_form 出现在不用它们的 kind 里即为错误。
L3 “片假名书写”：标题里片假名字符（含 ー）至少占一半（空格与 〜~・（）() 不计）。这样的词课都要有一条条目——来源条目，
   或 exempt 条目。
19.3 程序规则（I，2026-11-14；合成数据单元测试与 fake UI 测试，原生未验）
L4 纯模块 loanword_origins：格式校验（validate_entry／validate_namespace）、needs_origin、绑定（origin_for）、一行显示
   （origin_line、origin_note）、coverage（缺条目、过期、格式错、没有对应词课）与 candidate_count。
L5 构建的深度校验拒绝格式错误的命名空间（分片包与整份包都查），构建结果报告 candidate 条数；App 启动不校验，运行时格式
   错误、过期或缺失的条目一律不显示，不影响别的内容。
L6 显示为一行：“来源：葡萄牙语 pão”“来源：英语 coffee／荷兰语 koffie”“来源：英语 television 的缩略（テレビジョン）”
   “和制英语：salary＋man（英语里不这样说）”“混种词：オンライン←英语 online”；未审核的条目句末加“（待核实）”；exempt 不显示；
   note_zh 另起一行。位置：初次学习页读法行之下、批次说明卡词义之下（答错后重现的说明卡同样有）、学习库单词页读法行之下、
   作答结果“详细”标题之下。作答之前与作答之中一律不显示——跟着做、批小测、正式题，以及正式题里打开的说明卡：回想题要求
   写出这个片假名词，来源会泄露答案。词典详情页先列已审核的课程条目（带语言），词库自带的 Wiktionary 数据标“候选（未审）”，
   只有全部记录同属一种已列语言时才写语言名。
L7 扩展库可带同名命名空间，只为自己的词课写条目；合并按 id，同 id 冲突时核心优先并照常报告（08）。

  标 reviewed，不指定输出目录就不写内容目录。
